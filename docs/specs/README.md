# Specs

One file per GitHub issue the agent team works on: `docs/specs/<issue>-<slug>.md`, created
from [`_template.md`](_template.md). Using the issue number avoids collisions between
branches.

A spec is the shared context for one task: the designer frames the problem and writes the
brief, the planner sets the criteria and claims the files, the builder logs what it did, and
every reviewer's findings land in it. The PR links to it, so the whole conversation between
agents is in one place.

Merged specs stay here as the project's decision history — read related ones before
planning something new.
